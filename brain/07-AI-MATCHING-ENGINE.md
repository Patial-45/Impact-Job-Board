# AI matching engine (planned)

Pipeline: job description ingestion → structured requirement extraction → normalized job taxonomy → candidate profile/resume normalization → hard filters (eligibility, location, explicit constraints) → lexical/BM25 retrieval → vector retrieval → hybrid candidate set → deterministic feature scoring → reranking → evidence extraction → explanation → human review. An LLM never decides the entire ranking. Keep score version and model/prompt versions on each result; allow recomputation and audit.

Potential dimensions: skills, relevant experience, role similarity, seniority, industry, location, education, certifications, semantic similarity, requirement coverage and negative constraints. Hard requirements and inferred preferences must be separately labeled. Output includes score, matched/missing skills, experience alignment, cited profile evidence, concerns and calibrated confidence. Explain missing data rather than treating it as absence. Evaluate against human-labeled relevance and disparate-impact checks before production.

`packages/ai` defines LLM, embedding, structured-output and telemetry interfaces. Domain services such as `CandidateMatchingService`, `ResumeParsingService`, `JobParsingService`, and `SkillNormalizationService` will call them. Add provider adapters with retries, timeouts, usage tracking, redacted logging and fallbacks only as concrete workflows arrive. Prompt injection defense: treat uploaded resumes and JDs as untrusted data and constrain output schemas. No production matching is implemented in Phase 0.
