# Authentication and RBAC

Email/password registration and login use Argon2id. The API issues a random opaque token in an HttpOnly, Secure-in-production, SameSite=Lax cookie; only its SHA-256 hash is stored in PostgreSQL. Logout revokes the session. Expiration is seven days. Browser API calls use credentials. The web server verifies `/auth/me` for protected layouts; the API is the actual authorization boundary.

Global roles: `USER`, `PLATFORM_ADMIN`, `SUPER_ADMIN`. Workspace roles: `OWNER`, `ADMIN`, `RECRUITER`, `VIEWER`. Global roles do not bypass workspace membership. `PLATFORM_ADMIN` can eventually read platform administration; only `SUPER_ADMIN` may manage platform configuration. Workspace grants live in `packages/auth`; endpoint checks must resolve membership from the database and then evaluate the grant. Never trust a role from a request body or frontend state.

Google OAuth is modeled by `Account` but the flow is not implemented. Before enabling OAuth, use state/PKCE, explicit account linking, verified email policy, and secure refresh/token handling. Cross-site request risks are reduced by SameSite=Lax and origin checks on mutations; production should enforce trusted Origin/Referer for browser writes, with a CSRF token strategy if cross-site embeddings or multiple web origins are introduced. Login/register have tighter throttles. Rate limiting is process-local today; switch to a Redis-backed store before multiple API replicas. Require email verification and password reset before public launch. Do not log passwords, cookies, session tokens or OAuth credentials.
